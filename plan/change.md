# 客户端子世界识别算法补充约束

优先级：**高于 `pipeline.drawio` 和旧版规则**。当本文与流程图或旧版规则存在歧义或冲突时，以本文为准。

## P-3：临时歧义不得提前宣布“无法识别”

本节由真实 Velocity A/B 切换中“最终识别正确、但采证中途每次都弹无法识别”的现场回归确认，优先级高于本文全部后续章节。

- `AMBIGUOUS` 分数只是入口采证窗口内的中间结果，不等于已经需要人工选择。信号、三维入口点、轨迹连续性或有界地形探测仍可能更新时，状态必须保持采证并持续重算。
- 只有本轮有界采证窗口结束、地形总探测预算已用完或已无待采地形、仍然没有可准入候选时，才允许进入 `WAITING_FOR_USER` 并发送“无法识别”提示。
- 最后一次地形采证与重新评分必须发生在失败提示之前；同一 tick 能恢复身份时不得先发失败消息。
- 地形探测预算属于一次 recognition generation，而不是每个玩家经过的中心区块。高速飞行跨区块不得不断重置次数并让采证无限延长；稳定或 provisional 身份已经锁定后，新中心可以为后续验证另开预算。
- 同一 recognition generation 最多发送一次无法识别提示。出生点、普通信号刷新、移动或区块更新不得重置提示锁；只有新的真实身份边界、连接或用户明确操作才能开始新一轮。
- 人工选择界面可以在已有候选诊断时提前可用，但“允许用户主动打开”与“算法已经失败并主动打扰用户”必须分开。

## P-2：每个 profile 只允许一个最新维度与三维终点

本节由“主世界档案与地狱档案仍被旧维度坐标串联”的现场回归确认，优先级高于本文全部后续章节。

- 每个 profile 只能有一份用于连续性识别的最新状态：`dimension + position(X/Y/Z) + observedAt + recentTrajectory`。进入或保存另一个维度后，旧维度的位置与轨迹立即失去连续性资格。
- `visits[dimension]` 可以继续保留地形锚点与维度上下文，用于地图分层和地形验证；但历史维度中的 `lastPosition`、旧轨迹或旧访问时间不得作为当前候选的位置证据。
- 历史轨迹专指通向唯一最新终点的有界近期运动序列，不是跨维度、跨会话累积的历史坐标库。维度切换会截断旧轨迹并由新维度轨迹覆盖。
- 当前观察维度与候选最新维度不同时，该候选的位置/轨迹因素不可用；不得回退到该候选上一次到过当前维度时的旧坐标。历史地形仍可展示或验证，但不能制造位置连续性。
- 最后点距离使用 X/Y/Z 三维欧氏距离。预测线前进距离 `s` 沿预测方向计算；X/Z 横向偏差与 Y 高度偏差合成为三维空间偏离 `r`，再进入 0–1024 衰减乘数。
- proxy GameJoin 只有在 HEAD 阶段 profile 已经非 provisional 确认时，才允许把它作为 `departedProfileId` 硬排除。provisional 只是候选假设，不能取得排除下一轮候选的因果权力，否则一次误准入会形成 A/B 交替反转。
- 最佳候选位于 6/48 格带内且第二名位于带外时，可使用 3 个百分点的严格领先门槛；仍须达到对应队列总置信度、拥有连续性与足够独立因素且无硬冲突。半径外位置仍按 0–1024 公式衰减，不直接归零。
- 队列 1/2 的基础领先门槛统一为严格 `>3` 个百分点，不得因为本轮缺地形就私自提高到 10 个百分点；否则精确最后点的优势会被身份、上下文和游戏模式等同分项稀释。队列 3 仍保持严格 `>15` 个百分点。
- 本地开发测试必须固定离线用户名/UUID。更换玩家身份意味着服务端使用另一份玩家坐标档案，不能把这种跨玩家变化当作同一玩家的子世界连续性回归数据。

## P-1：最后点锚定的因果预测与事件驱动识别

本节由现场 A/B 回归确认，优先级高于本文全部后续章节，并覆盖旧文中“当前位置到整条历史路径最近点”的表述。

### 位置证据必须以最后点为基准

- 每个候选的位置锚点是断线/离开前最后一个客户端本地轨迹样本；缺少样本时才回退到独立保存的 `lastObservedPosition`。地形锚点和历史路径中的更早点都不能替代该位置锚点。
- 本轮识别位置是当前 connection generation 的第一个本地观察点，而不是玩家在识别后持续移动形成的整条当前轨迹。识别完成后的移动不得改变本轮入口点。
- 玩家静止或最后速度低于预测阈值时，预测段退化为最后点，直接以“当前入口点到候选最后点”的水平距离输入 0–1024 格归一化指数公式。
- 历史轨迹只能用于估计最后点处的速度和朝向；禁止遍历候选整条历史路径与当前整条轨迹并取任意线段最近距离。两条路线过去相交不能证明跨连接连续性。

### 前向预测线的纵向和横向必须共同衰减

- 预测线只能从候选最后点沿离开速度/朝向向前生成，最大 5 秒；断线间隔更长时仍只保留有界最大预测段，不能无限外推。
- 设入口点投影到预测段后的前进距离为 `s`、到该投影点的横向/段外剩余距离为 `r`，则：

```text
centerline_confidence = position_confidence(s)
lateral_multiplier    = position_confidence(r)
trajectory_confidence = centerline_confidence * lateral_multiplier * freshness
```

- 预测线自身必须从最后点开始随 `s` 衰减；横向衰减必须乘在投影位置已有的 `centerline_confidence` 上，不能在远端预测点旁边重新从 100% 开始计算。
- 当预测段长度为零时 `s=0`、`r=当前入口到最后点距离`，公式自然退化为最后点位置置信度。
- Minecraft 客户端速度是格/ tick，和按秒拟合的历史速度混合前必须换算为格/秒；否则预测段会缩短约 20 倍。

### resolver 只在身份事件上启动

- 连接建立、真实 GameJoin、明确区块整体替换、权威 Companion ID 或显式切换命令启动一轮识别。识别收集一个有界入口证据窗，选出 profile 后即锁定当前 observation generation。
- `WorldSessionTracker` 每 tick 读取当前身份必须是无副作用操作；普通移动、位置采样、地图快照和 UI 打开均不得重新运行 A/B 候选选举。
- provisional 后续只接受“确认当前锁定 profile”或“当前锁定 profile 发生硬冲突”两种身份结果。临时分数、领先差距、地形尚未完成或另一个候选分数上升不得旋转地图身份。
- 硬冲突只能暂停当前地图并进入重新识别/人工流程，不能在同一次验证调用中直接切到另一个候选。

### GameJoin 必须采用离开/到达两阶段边界

- `GameJoin` 包处理开始（HEAD）时，客户端仍持有离开世界的玩家、坐标、轨迹和区块；必须在此时完成离开档案与独立轨迹 checkpoint 的最终保存。
- `GameJoin` 包处理结束（TAIL）后，才允许清空旧世界观察、建立新的 observation/trajectory generation 并开始收集到达证据。禁止在 TAIL 使用已经被替换的客户端状态刷新离开档案。
- Velocity 内部后端切换仍属于同一网络连接：必须保留外层服务器地址/`serverId`，不得把它重置成一次新服务器连接。
- 刚在 HEAD 保存的 server 级轨迹 checkpoint 属于离开的后端，不能在同一次 proxy GameJoin 的到达阶段恢复为“当前入口轨迹”。只有真正的新网络连接/进程恢复才允许加载该 checkpoint。
- 每次真实 proxy GameJoin 必须开启新的轨迹代次。新一轮候选只比较新代次入口点；上一后端的当前轨迹只能作为对应候选已持久化的离开证据。
- provisional 会话的本地轨迹不得因“尚未地形确认”而丢失，也不得直接写入稳定 profile。独立 checkpoint 必须携带准入 `profileId` 与 observation generation，使其只作为该候选的未提交离开终点/速度证据；确认同一 profile 后合并，硬冲突或候选撤销时删除。
- provisional profile 在新维度尚未来得及形成正式 visit 就发生切服时，其带 `profileId` 的本地 checkpoint 必须作为该 profile 在该维度的临时候选证据；不得因为 registry 中缺少正式 visit 就把它直接标为 `dimension_unavailable`。该临时证据只参与本轮评分，确认前仍不得写入稳定 visit。
- 真实 proxy GameJoin 已经证明玩家离开了 HEAD 阶段的当前 profile。本轮到达选举必须把这个 `departedProfileId` 作为零权重硬否决项，禁止同一个边界立即重新选回刚离开的档案；普通断线重连和同后端维度传送不应用此规则。
- 候选轨迹的速度/朝向超过新鲜度窗口后停止外推，但它的最后本地点仍是该候选的位置锚点；不得因为速度过期而退回 profile 中更早的旧坐标。
- profile 已有现代 visit、但缺少当前维度 visit 时，只能将该候选标为“当前维度证据不可用”；不得冒充整个 profile 都无法评分的 `legacy_candidate_unresolved` 并硬拦截其他候选。只有 profile 完全没有现代 visit 时才属于真正 legacy。
- 世界边界对 `lastStable` 的抑制只取消上一会话先验贡献，不得抑制候选本身在当前维度的位置、轨迹、地形或其他证据；UI 必须把“因素被抑制”和“候选被淘汰”明确区分。

## P0：同 seed 档案完整性与决策可解释性修正

本节优先级高于本文后续规则。它修正当前实现中“创建或选择同 seed 档案后擦除另一个档案的 seed 绑定”“安全拦截返回空候选”和“UI 只显示总分、无法说明为什么拒绝自动选择”的问题。

### seed 成员关系不得被同 seed 选择破坏

- 同一个 seed 可以合法属于多个子世界档案。seed 只用于筛选兼容候选，不能被当成档案之间互斥的唯一所有权。
- 当次人工选择或创建档案只确认“这一次观察属于所选档案”，不能据此推断其他档案从未使用相同 seed。
- 选择或创建同 seed 档案时，不得仅因为新档案接收了当前 observation，就删除其他档案的同 seed 成员关系或完整历史绑定。
- 只有用户明确执行“清除识别记录”、现有档案已被权威证据证明绑定错误，或观察包含能够排除旧档案的真正互斥身份时，才允许移除旧绑定。
- seed 成员关系与用于排序的身份/访问信号必须在语义上分离。即使底层暂时仍使用同一持久化结构，实现也必须保证同 seed 多档案能够同时进入候选集合。
- 同 seed 多档案同时存在不代表可以自动选择；后续仍必须按连续性、轨迹、位置、地形、稳定信号和现有显式权威流程判断，无法区分时保持人工选择。

### 所有终止分支都必须产生候选诊断

- 安全硬拦截可以禁止自动选择，但不得通过返回空 `candidates` 隐藏已经存在的档案和证据。
- 同 seed 新子世界保护、观察不完整、领先差距不足、独立因素不足、队列门槛不足、稳定信号冲突、地形冲突和持久化失败都必须产生明确的决策结果。
- 每次识别至少记录：参与的候选、候选是否有资格、最终是否打分、未打分原因、阻止自动选择的具体门槛，以及还需要什么证据才能继续。
- 如果某条硬规则在正式综合打分前结束流程，仍应为每个可见档案建立“未评分/被前置规则拦截”的诊断项，而不是让 UI 显示成没有候选。
- 诊断只解释当前决定，不得为了生成说明而放宽冲突规则、提交 provisional 数据或改变候选身份。

### 候选必须携带完整的决策明细

- 候选结果不能只保存最终百分比、模糊原因字符串和冲突布尔值；必须携带结构化的决策明细。
- 每个候选至少应包含：
  - seed 筛选结果和是否属于同 seed 多候选；
  - 每个因素是否可用、原始置信度、配置原始权重、重归一化后的有效权重以及对总分的实际贡献；
  - 轨迹最近接近距离、本地证据年龄、服务端位置纠正年龄和连续性是否成立；
  - 最后稳定档案是否命中；
  - 身份信号与访问上下文的匹配数、可比较数和冲突项；
  - 游戏模式匹配结果；
  - 地形是否缺失、完整度、匹配分、是否达到 85% 高匹配或低于 60% 明确失配；
  - 所属队列、该队列最低分、所需领先差距、第二名分数和实际领先差距；
  - 独立证据数量、所有否决条件和最终决定。
- 缺失因素必须明确显示为“不可用并从权重中移除”，不能显示为零分证据，也不能让用户误以为它参与了惩罚。
- seed 预筛选、稳定冲突和明确地形失配属于筛选/否决规则，必须与普通加权贡献分开显示。
- 新增或重命名任何 resolver 原因时，必须同时补齐结构化枚举、中文/英文显示和测试；未知原因不得统一退化成没有含义的“其他证据”。

### 子世界列表和详情必须展示决定依据

- 列表每一行至少显示：档案名称、当前状态、最终分数或“未评分”、自动/人工结论，以及最关键的支持因素或阻止原因。
- 选中档案后的详情区域必须显示完整因素明细，包括原始值、有效权重、贡献、冲突、队列门槛和领先差距。
- 当前已经确认的档案也不得只显示“已确认”后提前结束详情；仍应说明它由人工选择、显式命令、连续性、地形或其他证据中的哪一条路径确认。
- 信息过多时采用“列表摘要 + 选中后完整详情”的两层展示；不得通过静默截断把关键阻止原因排除在可见区域之外。
- 因窗口尺寸被裁剪的单行内容必须可查看完整文本；因素明细需要可滚动、分页或等价的可达方式。
- UI 展示必须直接消费 resolver 产生的结构化决策明细，不能在界面层重新猜测权重或复算算法。

### 默认端口地址必须使用同一服务器身份

- 对 Minecraft 默认端口，`host` 与 `host:25565` 必须解析为同一个逻辑服务器身份；仅仅改变默认端口的书写方式不得创建一套新的子世界档案。
- 非默认端口继续保持独立，例如 `host:25566` 不得与 `host` 或 `host:25565` 合并。
- 地址规范化必须正确处理大小写、IPv4、DNS 名称和带方括号的 IPv6，不能通过简单截断冒险合并不同地址。
- 为兼容已有数据，加载时应识别省略默认端口和显式默认端口两个旧键。迁移必须非破坏性：不得覆盖已有 profile、地图目录、轨迹、地形锚点或最后稳定档案。
- 如果两个旧键下都已有内容，应先建立别名并执行可审计的合并；能够按稳定 profile ID 或存储 ID 确认相同的记录才去重，不能确认时保留双方并报告冲突。
- 地址别名处理只统一服务器入口身份，不得合并不同子世界的 `storageId`，也不得改变 Companion 或现有显式命令的权威优先级。

### 代理切换、位置纠正与旧稳定档案不得制造反向优势

- 服务端下发位置纠正包只证明纠正发生时的那个位置，不能被称为或当作服务器持续确认客户端移动的 ACK。玩家正常站立或正常移动时没有新位置纠正包，不得因此让当前本地轨迹自动变成陈旧证据。
- 历史候选轨迹的旧位置纠正时间不得扩大当前匹配走廊，更不得把相距几十或几百格的候选压成与当前位置完全重合的相同轨迹分。当前观察的新鲜度只由当前本地样本年龄衡量；历史路径坐标按真实最近距离参与比较。
- 6/48 格只决定队列。位置置信度必须直接对“当前连接入口点到候选最后点或从该点开始的有限前向预测段”的纵向/横向距离应用 0–1024 格指数曲线，不能先减去 6/48 格半径再评分；禁止使用整条历史路径的任意最近点。
- 已检测到 GameJoin、区块整体替换或其他上游世界边界时，旧 `lastStableProfile` 表示的是已经离开的后端，必须从本轮正向权重和冲突判断中移除。普通断线重连没有检测到上游切换时，最后稳定档案只能作为当前观测近似打平时的连续性先验：如果另一个候选已落入当前 6/48 格轨迹走廊，而旧稳定档案位于走廊外，旧稳定档案必须从本轮归一化权重中移除，不能反向覆盖更强的当前本地轨迹。
- `lastStable` 抑制和“刚离开的 profile”硬排除是两条不同规则：前者只移除加分，后者利用真实 GameJoin 的因果事实禁止原地选回。UI 必须分别显示，不能都写成模糊的“候选被抑制”。
- 同 seed 多档案在上游切换后仍允许使用位置、轨迹和其他辅助证据进入 provisional；旧最后稳定档案不得仅靠连续性先验反超一个与当前位置精确重合的候选。
- 列表因领先差距不足而拒绝自动选择时，必须直接显示实际领先百分点和所需严格门槛，例如“实际领先 10%，要求 >15%”，不能只显示模糊的“领先幅度不足”。
- UI 的完整诊断必须按“本轮决策 / 因素权重表 / 阻断与证据 / 档案信息”分区。因素权重表逐项显示原始分、配置权重、动态归一化后的有效权重、最终贡献以及参与/缺失/硬否决状态；不得再把所有贡献压成一条自然语言句子。

### provisional 是一次准入，不是逐 tick 重新竞选

- 某个 profile 已通过连续性规则进入 provisional 后，该决定在当前 observation generation 内保持稳定。玩家正常移动只更新本地轨迹和临时地图，不得因为当前位置逐渐远离旧档案锚点而每 tick 重新选举 profile。
- 只有新的 GameJoin/维度或区块整体替换等真实边界、seed/稳定信号冲突、明确地形失配、Companion 权威世界 ID 或用户显式选择，才能确认、替换或撤销当前 provisional 身份。
- 重新评分暂时把另一个兼容候选排到更高、领先差距变化或地形尚未采到，都不是旋转 provisional 地图身份的充分条件。当前 provisional 候选仍无硬冲突时，必须维持原地图会话和缓冲归属。
- provisional 快照必须立即写入仅当前 `MapWorld` 可见的内存层，使小地图和全屏地图可以正常显示玩家刚走过的区域；该路径不得触发 `RegionDiskCache`。确认后才把同一批缓冲标记为可持久化，冲突/撤销时随临时会话一起丢弃。
- provisional 尚未确认时仍必须周期性保存独立的本地轨迹检查点，不能只在稳定档案刷新或退出成功时保存。轨迹检查点不等于确认 profile，不得直接污染该 profile 的持久化访问记录。

### 本节验证要求

- 覆盖创建第二个同 seed 档案后，第一个档案仍保留 seed 成员关系，两个档案都能进入后续候选评分。
- 覆盖人工选择、人工创建、清除绑定和真正互斥身份纠正，验证只有明确授权或互斥证据才能移除旧绑定。
- 覆盖所有前置硬拦截均返回非空、可解释的候选诊断，并验证诊断不会改变识别结果或提交数据。
- 覆盖地形存在/缺失、因素动态重归一化、冲突否决、三个队列门槛和领先差距的逐项贡献值。
- 覆盖 UI 摘要、完整详情、未知原因检测、窄窗口裁剪和详情滚动可达性。
- 覆盖 `host`/`host:25565` 共享档案、非默认端口隔离、双旧键非破坏迁移及冲突报告。
- 覆盖现场回归：玩家位于 A 保存坐标、B 相距约 61 格且是旧最后稳定档案、两者同 seed/同地形时，A 必须高于 B；B 的旧位置纠正时间不得把 61 格距离吞入 208 格满分走廊。
- 覆盖普通重连现场回归：代理默认把玩家送回 A、持久化 `lastStableProfile` 仍指向 B 时，只要 A 在 48 格当前走廊内而 B 在走廊外，B 的旧稳定先验必须退出权重归一化，A 不得再次被 B 反超。
- 覆盖同一后端重复 GameJoin 后先 provisional A、下一 tick B 临时分数更高、随后玩家持续移动的现场回归：地图身份必须保持 A，不得 A→B 旋转或最终暂停；新经过区块必须立即可见但在确认前不落盘。

## PLAN-26-8-8-1007 最高优先级规则

- 连续性是普通重连的主证据：同一服务器的最后稳定 profile、客户端本地当前轨迹和历史轨迹必须在地形缺失时仍可参与恢复。
- 速度、朝向、采样时间和历史轨迹是正式输入，使用有限时间窗的预测走廊；轨迹不得无限外推，传送、维度切换、服务器纠正或无法解释的跳变必须截断轨迹。
- 地形是可选验证因素。未采到、历史中心未加载或 3x3 不完整时，移除地形项并对实际可用辅助因素重新归一化，不得因缺地形直接归零或强制人工选择。
- 完整且高匹配地形提供低权重正向证据；完整但明确失配是强反证，禁止该候选自动选择。
- 第一、第二、第三队列只控制检查优先级和采样资源，不是自动选择资格。辅助证据足够强、候选唯一且无冲突时，低队列也可以恢复；低队列不得覆盖高队列中的明确冲突。
- 自动恢复必须满足阈值、领先差距和独立证据数量要求；唯一 seed 不能单独作为充分条件。同 seed 多候选若要稳定确认并提交，仍需完整地形或 Companion 权威 ID 消歧；仅凭连续性最多进入 provisional。
- 连续性恢复但尚未验证时进入 `provisional`：新地图、地形和索引进入缓冲；确认后提交，冲突时丢弃并转人工选择。
- `lastObservedPosition`、历史轨迹、`terrainAnchors` 和 `lastStableProfile` 分开保存。旧地形锚点不得被移动到新坐标。

## 最高优先级实现修正

- 每个地形指纹必须持久化其 3x3 样本中心区块坐标。后续刷新访问位置时不得把旧指纹重新标记到新坐标。
- 比较候选档案的地形前，候选指纹保存的完整 3x3 必须已经在客户端加载；“已加载”专指保存指纹中心及其周围九个区块都存在于当前客户端 chunk manager，不能用玩家附近其他区块替代，也不能主动加载历史区块。只能以不触发加载的读取方式采样。任意一个区块缺失时，该候选地形证据不可用并降级。
- 完整样本的普通地形通过阈值为 85%，用于高匹配和同 seed 消歧；低于该值仍可作为弱正向证据，明确失配才否决自动选择。
- 1.5 格缓存复用必须同时满足：维度相同、候选保存坐标水平距离不超过 1.5 格、观测与候选地形证据均完全相同。缓存只复用 `Match` 计算结果，绝不共享档案身份、存储空间或不同证据的地形得分。
- 地形计算仍在重试时，只要已经产生 `AMBIGUOUS` 候选结果，人工选择必须立即可用（不依赖信号采集是否已经结束）；自动选择仍需等待完整的当前结果。
- 不得以“仅剩一个候选档案”为由绕过维度、坐标、地形和自动选择条件。
- 普通自动识别缺少维度时仍不得匹配；缺少坐标或地形时可使用有效连续性和辅助因素恢复，但不得仅凭唯一 seed 或单一信号恢复。显式指令和当次人工选择只对该次明确操作生效，不得降低后续自动识别门槛。
- 自动选择不再限定第一队列；队列只控制检查顺序。低队列候选必须满足更严格的辅助证据和领先差距要求，且不得绕过高队列中的明确冲突。
- 稳定档案在玩家跨区块后的访问刷新必须持久化当前玩家中心新采集的地形指纹。为候选匹配而读取的历史中心样本只能作为当次候选证据，不得覆盖该稳定档案的新指纹中心。
- 如果当前中心 3x3 尚未完整采集，稳定档案可以更新独立的 `lastObservedPosition` 和轨迹，但不得移动或伪造旧地形锚点。
- 仅原版 `minecraft_the_nether` 使用 6 格半径；所有其他维度，包括名称中含有 `nether` 的自定义维度，默认使用 48 格半径。

## 目的

为流程图中的队列、坐标置信度、地形指纹和自动选择条件提供可实现、可测试的精确定义。

## 匹配顺序

1. 命中已配置的切换指令时，沿用原有显式切换逻辑，不执行自动匹配。
2. 未命中指令时，先按服务器地址与 seed/seed hash 筛选候选。
3. 对剩余档案按维度、坐标和地形指纹进入最多三级队列；低优先级队列不得覆盖高优先级队列中的有效候选。
4. 所有队列均不能产生唯一可信候选时，进入人工选择，不猜测世界。

## 队列定义

- 第一队列：维度相同、坐标在允许半径内，并且存在完整可比较的 3x3 地形指纹。
- 第二队列：维度相同，但坐标或地形指纹证据不完整。
- 第三队列：没有同维度访问记录，或坐标超出允许半径。
- 候选存在稳定信号冲突时，不参与自动选择，但继续显示在人工选择候选中。

## 坐标边界和置信度

- Nether 坐标半径为 6 格；Overworld、End 和未知自定义维度默认半径为 48 格。
- 半径边界包含在匹配范围内。
- 6/48 格半径只决定队列优先级；距离在半径外时位置置信度继续衰减，不得直接归零。
- 距离大于或等于 1024 格时，位置置信度为 0；距离为 0 时为 1。
- 0 到 1024 格内采用归一化指数衰减：

```text
position_confidence = (exp(-4 * distance / 1024) - exp(-4)) / (1 - exp(-4))
```

- 使用速度、视角、时间差和历史轨迹预测有限走廊；预测范围随确认间隔扩大，前向预测段在最大时间窗外失效，但已观测历史路径保留并按确认年龄衰减。

## 综合置信度

- 连续性/辅助因子是主权重，地形仅作低权重验证；当前实现使用辅助 75%、地形 25% 的保守基线，后续只能通过固定数据集校准。
- 辅助因子内部包含预测/历史轨迹、游戏模式和维度访问上下文；只在实际可用因子之间归一化。
- 地形指纹必须是完整 3x3 样本；不完整样本视为不可用并降级队列。
- 地形指纹不可用时，移除地形项并对归一化后的辅助分数重新评分；不得因缺失把候选分数设为零。
- 自动选择要求：最高分不低于 60%，没有稳定信号冲突或明确地形失配，独立辅助因素达到最低数量，且与兼容第二名差值严格大于 3 个百分点。低队列使用更严格的辅助模式阈值。
- 同 seed 的多个候选仍必须由地形指纹明确区分；地形得分至少 85%，且相对其他兼容候选至少高 10 个百分点。

## 缓存和异步边界

- 缓存只在单次匹配调用内有效，调用结束立即丢弃，不写入跨会话状态。
- 同一对观测指纹与候选指纹只计算一次；候选档案始终保持独立，不合并身份或存储空间。
- 流程图中的 1.5 格复用半径只可用于复用完全相同证据的计算结果，不得用相邻档案的地形结果替代当前档案的独立指纹。
- 核心匹配不得等待区块加载；地形样本未完成时只将地形项标记为不可用并继续评估连续性。若辅助证据足够可进入 `provisional`，否则由现有探测状态机重试或进入人工选择。

## 验证要求

- 覆盖 Nether 6 格与其他维度 48 格的边界内、边界上和边界外用例。
- 覆盖指数置信度单调递减及超范围归零。
- 覆盖地形可用时辅助/地形 75/25 加权、地形缺失时辅助因素重归一化、3% 差值门槛、同分候选和稳定信号冲突。
- 覆盖不完整地形指纹降级、同 seed 多候选拒绝猜测和单次缓存不泄漏到后续匹配。
